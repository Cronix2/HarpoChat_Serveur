# P3 — `harpochat-server` M0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone `harpochat-server` binary that an operator can install, initialise (`init [--root]`), sanity-check (`run --check`) and run, published by a tag-triggered GitHub release with signed checksums for Windows x86_64, Linux x86_64 and Linux aarch64 (spec §12, milestone M0).

**Architecture:** New crate `crates/harpochat-server` (binary + library for tests). The library holds `config` (TOML), `keystore` (the only persistent file besides config, spec §4.1), `node` (descriptor building) and `cli`. No networking yet (P4). Keys come from `harpochat-core::keys`.

**Tech Stack:** `clap` 4 (derive), `toml` 1, `serde`, `tracing` + `tracing-subscriber`, `tokio` (signal + runtime only), `hex`; dev: `tempfile`. Release: GitHub Actions matrix, `cargo-zigbuild` for musl targets, `cosign sign-blob` keyless (GitHub OIDC) for `SHA256SUMS`.

**Spec:** `docs/SERVER_SPEC.md` v0.2 §4.1, §10, §12; design `docs/superpowers/specs/2026-11-26-harpochat-core-design.md` §3, §5.1, §5.8.

## Global Constraints

- Only two persistent files: `harpochat-server.toml` and `node.key` in the data directory (spec §4.1). Nothing else is written to disk, ever.
- Logs: startup, shutdown, configuration errors only (spec §10). Never log keys, token secrets, IPs of clients.
- `node.key` permissions `0600` on Unix; on Windows the file is created inside the user's data dir (ACL hardening deferred to P8, noted in operator doc).
- No network access at startup other than configured peers (P4); P3 opens no socket at all.
- Default data dir: `--dir` flag, else `$HARPOCHAT_HOME`, else `./harpochat-data`.
- Exit codes: `0` ok, `1` runtime error, `2` usage/config error.
- Release profile from workspace (`panic = "abort"`, stripped, LTO).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; branch `feat/p3-server`.

## Review Focus

1. **`init` run twice, or on a directory with a foreign `node.key`** → refuse, never overwrite keys (Task 3, `init_refuses_to_overwrite`).
2. **Hand-edited TOML with a typo'd key or a non-`wss://` public endpoint** → clear error naming the field, exit 2 (Task 1, `unknown_field_rejected`, `bad_endpoint_rejected`).
3. **Truncated or corrupted `node.key`** → `run --check` fails cleanly with exit 1, no panic (Task 2, `corrupt_keyfile_rejected`).
4. **Non-root node with no roots configured** → `run --check` refuses: it could never join (Task 4, `non_root_without_roots_rejected`).
5. **`--dir` path that does not exist / is a file** → create it on `init`, clear error otherwise (Task 3, `init_creates_dir`, `init_dir_is_file_rejected`).

### Task 1: Crate scaffold and configuration

**Files:** Create `crates/harpochat-server/{Cargo.toml,src/lib.rs,src/main.rs,src/config.rs}`; modify workspace `Cargo.toml` (member + deps).

**Interfaces — Produces:**
- `pub struct Config { pub node: NodeSection, pub listen: ListenSection, pub roots: Vec<RootConfig>, pub limits: Limits }` (`serde`, `deny_unknown_fields`, `Default`).
- `NodeSection { pub roles: Vec<Role>, pub layer: u8, pub public_endpoints: Vec<String>, pub root: bool }` — default roles = all three, layer 0, no endpoints, root false.
- `ListenSection { pub addr: String }` — default `"0.0.0.0:443"`.
- `RootConfig { pub id_pub: String /* 64 hex */, pub endpoints: Vec<String> }`.
- `Limits { pub mailbox_max_blobs: u32 = 1000, pub mailbox_max_bytes: u64 = 50 MiB, pub global_ram_bytes: u64 = 512 MiB, pub blob_ttl_secs: u64 = 7 days }`.
- `impl Config { pub fn parse(text: &str) -> Result<Self, ConfigError>; pub fn to_toml(&self) -> String; pub fn validate(&self) -> Result<(), ConfigError>; pub fn root_ids(&self) -> Result<Vec<[u8; 32]>, ConfigError> }`.
- `pub enum ConfigError { Parse(String), Invalid { field: &'static str, reason: String } }` with `Display`.
- Validation: `public_endpoints` each pass `harpochat_core::descriptor::validate_endpoint`, 0..=4 entries; `layer <= 2`; roles non-empty, no duplicates; root `id_pub` is 64 hex chars; limits non-zero, `blob_ttl_secs <= 7 days`.

- [ ] Tests (`config.rs`): `defaults_are_valid`, `roundtrip_toml`, `unknown_field_rejected` (error mentions the field), `bad_endpoint_rejected` (`field == "node.public_endpoints"`), `bad_root_hex_rejected`, `ttl_above_spec_rejected`.
- [ ] Run → FAIL; implement; run → PASS; clippy; commit `feat(server): crate scaffold and TOML configuration`.

**Interfaces — Produces:**

- `pub const KEY_FILE: &str = "node.key";`

### Task 4: Node descriptor and `run`

**Files:** Create `src/node.rs`; modify `src/cli.rs`.

**Interfaces — Produces:**
- `pub struct Node { pub config: Config, pub keys: NodeKeys, pub sphinx: X25519Secret, pub sphinx_epoch: u32 }` with `pub fn load(dir: &Path) -> Result<Node, NodeError>` (config parse + validate + keys load; fresh Sphinx key in RAM, `sphinx_epoch = now / (7 * 86_400)`).
- `pub fn descriptor(&self, now_unix_secs: u64) -> Signed<NodeDescriptor>` — `valid_until = now + 24 h`, roles/layer/endpoints from config, `noise_pub`/`sphinx_pub` from keys.
- Rule: non-root config with empty `roots` → `NodeError::Config(Invalid { field: "roots", .. })`; root config adds its own id implicitly.
- `run --check`: `Node::load`, build and self-verify the descriptor, print `ok: node <id8> roles=… endpoints=…`, exit 0. Without endpoints, warn that the node is not reachable.
- `run`: same, log one startup line, then wait for Ctrl+C (`tokio::signal::ctrl_c`) and log shutdown. (Networking arrives in P4.)

- [ ] Tests: `descriptor_is_valid` (`verify()` ok and `descriptor::validate` ok at `now`), `non_root_without_roots_rejected`, `run_check_ok_after_init_root` (CLI, exit 0, stdout starts with `ok:`), `run_check_missing_keys` (exit 1), `run_check_output_has_no_secret` (stdout/stderr contain neither the identity seed hex nor the noise secret hex).
- [ ] Run → FAIL; implement; PASS; commit `feat(server): node descriptor and run command`.
